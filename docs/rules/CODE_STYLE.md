# Code style rules

- Write code, identifiers, and project documentation in English.
- Follow repository formatter and lint rules; do not invent parallel rules.
- Prefer clear names and small, focused functions.
- Reuse installed dependencies and existing patterns before adding code or packages.
- Avoid speculative abstractions, duplicate sources of truth, and hidden side effects.
- Validate external or persisted data at its boundary.
- Preserve useful error messages and handle failure states explicitly.
- Comment only non-obvious reasons or constraints.
- Keep changes within the approved scope.
