# Angular rules

- Select the latest stable Angular version available at implementation time, subject to corporate approval.
- Use standalone Angular APIs and current supported patterns unless a repository standard says otherwise.
- Keep TypeScript strictness enabled.
- Use Angular CDK and Tailwind CSS for their approved roles; avoid duplicating behavior.
- Keep templates accessible: labels, keyboard operation, focus behavior, and clear error states.
- Follow established routing, state, and dependency-injection patterns.
- Check framework and package compatibility before installation or upgrade.
- Do not add an Angular package or UI library without checking corporate approval and maintenance status.

The specific Angular release, CLI setup, styling integration, and test runner remain to be selected and validated.
