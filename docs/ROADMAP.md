# Roadmap

The sequence follows the eight stages requested for the project. Weeks are reference points, not deadlines. Only phases 01 and 02 have detailed plans in this package. Every phase starts with human approval and ends with acceptance, independent audit, and documented evidence.

| Phase | Theme | Planned outcome | State |
|---|---|---|---|
| 01 | Foundations and project | Confirm foundation, repository baseline, README, and approved first product slice; include an AI capability only after its feasibility gate | Planned; detailed plan included |
| 02 | Context and rules | Establish persistent project context and concise agent rules; evaluate whether an agent follows them | Planned; detailed plan included |
| 03 | Specs and planning | Write feature requirements and acceptance criteria; plan and implement one approved feature from a spec | Planned |
| 04 | Reusable skills | Identify a repeated task, create a reusable SKILL.md, and use it for a second task | Planned |
| 05 | Specialized agents | Define architect, developer, and QA responsibilities, boundaries, and tool access; evaluate delegation | Planned |
| 06 | Workflows | Document the end-to-end workflow, approvals, and one useful automated validation | Planned |
| 07 | Testing and quality | Expand automated tests, fix a bug through a spec-led workflow, and record a quality review | Planned |
| 08 | Integration and demo | Integrate approved work, record decisions and limitations, and prepare a demonstration | Planned |

## Product scope

The 16 selected Bug Briefs capabilities are listed in [requirements](features/bug-briefs/REQUIREMENTS.md). They have not been assigned P0/P1/P2 priorities or mapped to phases in this package. Make that decision in a reviewed plan; do not present an agent's suggested ordering as an owner-confirmed commitment.

## Phase progression

- Review the phase plan and acceptance criteria before implementation.
- The owner explicitly approves the phase gate.
- Validate against acceptance criteria, audit, and document evidence.
- Resolve findings affecting correctness, security, privacy, accessibility, or data integrity before acceptance.
- The owner records acceptance before the next phase begins.
